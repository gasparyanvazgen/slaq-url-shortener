# ADR-001: Layered architecture and feature-module layout

- Status: Accepted
- Date: 2026-11-19
- Decision owner: User
- Register entry: D1 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

The MVP is one feature — short links — with three concerns that must stay separable: HTTP handling,
business rules (code generation, alias conflicts, expiry), and persistence. `AGENTS.md` §4 requires
layering, and `docs/testing-strategy.md` needs the service and generator testable without opening a
port. The proposal offered packages by layer versus packages by feature, and left the app factory's
signature open (`createApp(db)`).

## Decision

Adopt four layers inside a single feature module: **routes → controllers → services → repository**,
under `src/modules/links/`.

- Routes map method + path to a controller; they hold no logic and never parse input.
- Controllers parse and validate input, call a service, and shape the HTTP response. They never run
  SQL. Validation has exactly one owner: the controller applies the module's zod schema
  (`links.schemas.ts`).
- Services own business rules and never touch Express `req` or `res`. They throw typed application
  errors.
- Repositories own SQL only and return plain typed objects.
- One centralized error middleware maps application errors to the documented envelope; a separate
  not-found handler covers unmatched routes.
- Dependencies are injected through factories. The app factory takes a **deps object**:
  `createApp({ db, clock, config })`. It builds the repository and the link service from those
  dependencies; services are created as `createLinkService({ repo, clock, config })`, and nothing in
  the service reads configuration or time from a module global. Tests pass an in-memory database
  and a frozen clock through the same object.

## Alternatives considered

- **Single `app.ts` with inline handlers**: fastest to write for five routes, but mixes SQL, rules,
  and HTTP, so most behavior can only be tested over HTTP and the layers cannot be reviewed
  independently.
- **Global `controllers/`, `services/`, `repositories/` folders**: conventional, but for one feature
  it scatters a single change across four directories and adds navigation cost with no boundary
  benefit.
- **`createApp(db)` with a module-level clock and config**: fewer arguments, but hides two
  dependencies, makes expiry tests depend on real time or module mocking, and forces config reads
  from `process.env` deep in the call stack. The user chose the explicit deps object instead.
- **Constructor-injected classes**: equivalent testability with more ceremony than the project's
  style needs.

## Consequences

- Every dependency a handler needs is visible in one signature, which is also what the D17
  `PUBLIC_BASE_URL` rule and D15 injected clock require.
- Adding a second feature means adding a sibling module, not editing shared top-level folders.
- A controller that needs a new dependency changes `createApp`'s call site in `server.ts` and the
  test helper — a deliberate, small cost.
- Path aliases stay unnecessary (D10), and relative imports keep their `.js` extensions (D16).

## Implementation impact

- `src/app.ts` exports `createApp({ db, clock, config })`; `src/server.ts` supplies the real
  database, the real clock, and the validated config.
- `src/modules/links/` holds `links.routes.ts`, `links.controller.ts`, `links.service.ts`,
  `links.repository.ts`, `links.schemas.ts`, `links.types.ts`.
- `src/lib/errors.ts`, `src/lib/code-generator.ts`, `src/middleware/error-handler.ts`, and
  `src/middleware/not-found.ts` sit outside the module as shared infrastructure.
- `tests/helpers/test-app.ts` calls `createApp({ db, clock, config })` with an in-memory database
  and a fixed clock.
- `TASKS.md` §1 and §2, `ROADMAP.md` Phase 3–4, and `docs/architecture-proposal.md` §1–2 reflect the
  layout.

## Clarification (2026-11-19)

The Prompt 03 architecture review (correction C-1) found that the bullets above described both routes
and controllers as validating. The user approved the single-owner rule: **the controller validates**,
using `links.schemas.ts`; routes only map method and path. Layer boundaries, the deps object, and the
centralized error middleware are unchanged.

## Verification

Structural review against `AGENTS.md` §4 and the test plan; nothing to install. The deps-object
signature is proven only when `createApp` is written and the service tests run without a port. No
code exists yet, so no test ran.
