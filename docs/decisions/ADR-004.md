# ADR-004: Redirect status `302`

- Status: Accepted
- Date: 2026-11-19
- Decision owner: User
- Register entry: D4 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

`GET /:code` must send the client to the stored destination and count the click (FR-03/FR-04). The
status code decides whether that counting keeps working: browsers cache `301` responses
indefinitely, and a cached redirect never reaches the server again.

## Decision

`GET /:code` answers **`302 Found`** with `Location` set to the exact stored destination and no
response body.

- The click count is incremented for the same request that produces the `302`, and only after the
  redirect decision is made (D7).
- Only a destination that passed D18 validation can reach `Location`.
- No `Cache-Control` override is added beyond Express defaults.

## Alternatives considered

- **`301 Moved Permanently`**: fastest for repeated visits and cache-friendly, but browsers may cache
  it permanently, so clicks after the first visit are silently lost — it breaks the statistics the
  product exists to provide.
- **`307 Temporary Redirect`**: preserves the request method, which matters for non-GET methods.
  This route is only reachable by `GET`/`HEAD`, so it changes nothing for the client while being the
  less familiar status for a navigation redirect.
- **`308 Permanent Redirect`**: same permanence problem as `301`, with method preservation this
  route does not need.
- **`200` with an HTML or JSON body containing the URL**: no caching risk, but it is not a redirect;
  clients and browsers would have to follow it themselves.

## Consequences

- Repeat visits always reach the server, so `click_count` reflects real traffic.
- Each redirect costs one lookup and one update; accepted at MVP scale.
- If a link's destination is wrong, the fix takes effect immediately for every client — no stale
  cached redirects to flush.
- Caching proxies may still cache the `302`, but only for the short default they apply; the count
  stays meaningful.

## Implementation impact

- `links.controller.ts` uses `res.redirect(302, originalUrl)` and lets the service perform the
  count, or performs the count first and redirects only on success, matching the conditional-update
  pattern in `docs/database-design.md`.
- `docs/api-specification.md` documents `302 Found` and the `Location` header.
- `docs/ai-workflow/TASKS.md` §4 covers the status and exact header assertion.
- `docs/requirements.md` FR-03 and FR-04 rest on this decision.

## Verification

Express documents `res.redirect(status, url)` with an explicit status, so the code passes `302`
rather than relying on the framework default. No server exists, so nothing was run; the first check
is an integration test asserting `302` and an exact `Location` value.
