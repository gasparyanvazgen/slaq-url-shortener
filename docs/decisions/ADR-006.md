# ADR-006: Alias rules, case sensitivity, and reserved names

- Status: Accepted
- Date: 2026-11-19
- Decision owner: User
- Register entry: D6 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

A custom alias becomes the first path segment of a redirect URL, so its character set has to be
URL-safe without encoding and its comparison rule has to match how the database stores it.
`UNIQUE(code)` is case-sensitive by default (SQLite's BINARY collation), and the redirect
namespace already contains `/api` and `/health` (D3). The proposal fixed length and charset but left
the case-sensitivity question open.

## Decision

- Length: **3–32** characters.
- Charset: `[A-Za-z0-9_-]` only (letters, digits, hyphen, underscore). No dots, slashes, spaces, or
  percent-encoding.
- Comparison is **case-sensitive**: `Promo` and `promo` are two different aliases, matching the
  default BINARY collation of `UNIQUE(code)`. Aliases are stored exactly as submitted.
- Reserved names, tested case-insensitively: **`api`** and **`health`**. `API`, `Api`, and `HEALTH`
  are reserved too, because a browser, proxy, or client may case-fold a path segment.
- Failures: length or charset violation → `400 VALIDATION_ERROR`; reserved name → `400
  RESERVED_ALIAS`; already-used alias → `409 ALIAS_TAKEN`.

## Alternatives considered

- **Case-insensitive aliases** (`COLLATE NOCASE`): friendlier when a link is read aloud, but it
  requires a `NOCASE` unique index, a documented canonical form for how a code is echoed back, and a
  rule for what happens when a user asks for `promo` after `Promo` exists. Case-sensitive matching
  keeps validation, storage, and echo identical.
- **A broader reserved list** (`links`, `stats`, `favicon.ico`, `robots.txt`): safer if top-level
  routes are added later, but every entry is a name users cannot have for no present benefit. The
  list grows in the same change that adds a route.
- **Case-sensitive reserved-name check**: simpler, but `GET /API` would then reach the redirect
  handler and could be claimed as an alias, shadowing the API for case-folding clients.
- **Allowing dots or slashes**: enables `my.link` or `promo/2026`, and creates path-segment and
  extension ambiguity in routing, proxy rules, and file naming.
- **Allow 1–2 character aliases**: nicer for vanity links, but they collide with real route names
  far more easily and are the first names to be squatted.

## Consequences

- Every accepted alias is a single URL-safe path segment needing no encoding.
- Two aliases differing only in case can coexist; clients must use the exact case.
- Reserved names cover the only two static first segments the app owns. Adding a top-level route
  later requires adding its name here in the same change.
- Alias length is enforced in validation only — the schema deliberately omits
  `CHECK (length(code) BETWEEN 3 AND 32)` (D2), so generated 7-character codes are never at risk of
  violating it either.

## Implementation impact

- `links.schemas.ts` holds the Zod alias schema: string, trimmed, 3–32, regex `^[A-Za-z0-9_-]+$`,
  and a refinement that rejects `api`/`health` case-insensitively with `RESERVED_ALIAS`.
- `links.service.ts` maps a `UNIQUE` violation on insert to `ALIAS_TAKEN` and does not pre-check
  existence, so a concurrent create cannot slip between check and insert.
- `links.repository.ts` matches codes with `WHERE code = @code` on the default collation.
- `docs/api-specification.md`, `docs/requirements.md` (FR-02/FR-07), and `docs/testing-strategy.md`
  are aligned.

## Verification

Regex, length, and reserved-name rules are pure functions, and `UNIQUE` is the storage guarantee.
Nothing is implemented, so no test ran. The first checks are alias validation cases (too short, too
long, illegal character, `API` reserved) and a `409` on a duplicate alias.
