# ADR-008: API integration testing with `supertest`

- Status: Accepted
- Date: 2026-11-18
- Decision owner: User
- Register entry: D8 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

API integration tests assert a status code together with a header (`Location`, `Cache-Control`) or
a JSON body. The approved app factory (`createApp(deps)`, D1) is importable without binding a
socket, so tests do not need a long-lived server. Two options were viable: `supertest`, or Node's
built-in `fetch` against `app.listen(0)`.

## Decision

Use `supertest@^7.3.2` with `@types/supertest@^7.2.1` as **dev-only** dependencies. Tests pass the
app instance to `supertest`, which opens an ephemeral loopback listener for each request and closes
it; the suite binds no fixed port and writes no listener lifecycle.

## Alternatives considered

- **Node `fetch` + `app.listen(0)`**: no extra dependency and closer to production sockets, but
  every test file needs `listen`/`close` lifecycle handling plus hand-written header and body
  assertions, which invites leaked servers and `EADDRINUSE` failures.
- **`node:test` + `fetch`**: duplicates the chosen runner (Vitest) and adds no assertion helpers.
- **Direct controller invocation**: skips the HTTP stack, so it cannot verify status codes or
  headers — not an integration test.

## Consequences

- Two dev-only packages enter the lockfile; the runtime dependency set is unchanged.
- Redirect and header assertions stay short, matching the test inventory in
  `docs/testing-strategy.md`.
- `supertest` exposes `res.body` as `any`; tests must narrow it to a declared response type, or
  type-aware linting (D11) reports `no-unsafe-*` findings.

## Correction (2026-11-19)

The Prompt 03 architecture review (correction C-3) found that "no port is bound" was inaccurate:
`supertest` given an Express app starts an `http.Server` on an ephemeral loopback port per request
and closes it. The decision stands; only the description changed, and the practical property it was
meant to convey — no fixed port, no manual lifecycle in the suite — is preserved here and in
`docs/testing-strategy.md`.

## Implementation impact

- `TASKS.md` §1 adds `supertest` and `@types/supertest` to dev dependencies.
- `tests/helpers/test-app.ts` builds the app in-process; `tests/links.api.test.ts` drives it.
- `docs/testing-strategy.md` names `supertest` as the API harness.
- `docs/architecture-proposal.md` §6 lists it as an approved dependency.

## Verification

Registry check 2026-11-18: `supertest` 7.3.2, `@types/supertest` 7.2.1. Express 5 compatibility is
expected but **unproven**: no dependency is installed and the AGENTS.md §8.2 gate cannot run
without a `package.json`.
