# ADR-010: TypeScript 6.0.3 with a no-emit typecheck config and a separate build config

- Status: Accepted
- Date: 2026-11-18
- Decision owner: User
- Register entry: D10 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

Type-aware ESLint (D11) requires a TypeScript version inside `typescript-eslint@8.73.0`'s peer range
`>=4.8.4 <6.1.0`, and TypeScript 7.x has no programmatic compiler API for that use. Typechecking
must also cover tests, while the build must not ship them.

## Decision

Use `typescript@^6.0.3` with two explicit configs.

`tsconfig.json` — typecheck and editor, never emits:

- `target: "es2023"`, `lib: ["es2023"]`
- `module: "nodenext"`, `moduleResolution: "nodenext"`
- `types: ["node"]` — TypeScript 6 defaults `types` to `[]`, so Node globals must be listed
- `strict: true`, `noUncheckedIndexedAccess: true`, `noImplicitOverride: true`,
  `noFallthroughCasesInSwitch: true`
- `noEmit: true`, `skipLibCheck: true`, `forceConsistentCasingInFileNames: true`
- `include: ["src", "tests", "vitest.config.ts"]`

`tsconfig.build.json` — extends the above and emits:

- `noEmit: false`, `rootDir: "src"`, `outDir: "dist"`, `sourceMap: true`, `declaration: false`
- `include: ["src"]`

Scripts: `"typecheck": "tsc -p tsconfig.json"`, `"build": "tsc -p tsconfig.build.json"`. TypeScript
6 makes a bare `tsc file.ts` an error while a tsconfig exists, so `-p` is always passed.

## Alternatives considered

- **One emitting config**: either ships tests into `dist/` or needs `exclude` rules that silently
  drop files.
- **TypeScript 7.0.2** (registry `latest`): outside the peer range; would force dropping type-aware
  linting.
- **CommonJS with `moduleResolution: node10`**: `node10` is removed in TS 6 and CJS conflicts with
  the ESM direction of D16.
- **`bundler` resolution plus `tsup`/`esbuild`**: a second module semantics and an extra
  dependency for no MVP benefit.
- **`verbatimModuleSyntax`, `exactOptionalPropertyTypes`, `allowJs`, `declaration`, path aliases**:
  deliberately omitted — friction at the CJS `export =` typings boundary, noise with Zod optional
  fields, no JS sources, no consumers, and unnecessary aliasing in a shallow tree.

## Consequences

- `types` must stay explicit or Node globals disappear after a TS upgrade.
- `rootDir: "src"` in the build keeps the entry point at `dist/server.js`, as D16 requires.
- Two configs can drift, so the build config may only override emit-related keys.

## Implementation impact

- `TASKS.md` §1 creates both files and the two scripts.
- `docs/coding-standards.md` records the options and the `-p` rule.
- `docs/research-findings.md` §3 holds the full configuration text used as the source.

## Verification

Peer range and TypeScript 6 changes verified 2026-11-18 against the npm registry and release notes.
The configs are **unproven**: no `package.json` exists, so `tsc -p` has not run.
