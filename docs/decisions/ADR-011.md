# ADR-011: ESLint 10 flat config with type-aware linting

- Status: Accepted
- Date: 2026-11-18
- Decision owner: User
- Register entry: D11 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

ESLint 10 removed the `.eslintrc` system, so a flat config is mandatory. The project's highest-risk
mistakes are typing and async mistakes around the SQLite driver and Express handlers, which
type-aware rules catch and non-type-aware rules cannot.

## Decision

- `eslint@^10.15.0`, `@eslint/js@^10.0.1`, `typescript-eslint@^8.73.0`, `globals@^17.14.0`.
- One `eslint.config.js` (ESM) using `js.configs.recommended` plus
  `tseslint.configs.recommendedTypeChecked`, with `globals.node` and
  `parserOptions: { projectService: true, tsconfigRootDir: import.meta.dirname }`.
- Plain `.js` config files disable type-checked rules.
- Script: `"lint": "eslint ."`.

## Alternatives considered

- **`recommended` (non-type-aware)**: faster, but blind to floating promises, unsafe `any`, and
  misused driver types.
- **Prettier in addition**: another dependency and a formatting debate the brief never requested.
- **ESLint 9 with `.eslintrc`**: legacy configuration model, removed in 10.

## Consequences

- Linting depends on a valid `tsconfig.json` and on the TypeScript version approved in D10.
- `lint` and `typecheck` overlap but are not redundant: rules such as `no-floating-promises` and
  `no-unsafe-*` require type information and are not compiler errors.
- Lint must stay clean without rule suppressions; a genuine exception requires an explicit,
  reviewed decision.

## Implementation impact

- `docs/ai-workflow/TASKS.md` §1 creates `eslint.config.js` and the `lint` script.
- `docs/coding-standards.md` records the configuration model and the no-suppression rule.
- `docs/ai-workflow/research-findings.md` §4 holds the config text.
