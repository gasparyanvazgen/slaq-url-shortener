# ADR-012: `better-sqlite3` 13 with separate typings and three typed helpers

- Status: Accepted
- Date: 2026-11-18
- Decision owner: User
- Register entry: D12 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

The project needs a synchronous SQLite driver that installs without a compiler toolchain and works
on the approved Node 24 runtime (D13). The chosen package ships prebuilt N-API binaries
(`gypfile: false`, `engines.node >= 22`) but **no bundled types**, and its DefinitelyTyped typings
have two gaps that would otherwise force `any` or a lint suppression.

## Decision

- Use `better-sqlite3@^13.2.0` with `@types/better-sqlite3@^9.6.0`.
- Absorb the typing gaps in three small helpers, never with `any`:
  1. `pragmaValue<K>(db, name)` — `pragma()` is typed `unknown`; one documented cast behind a
     `PragmaMap` keyed by the pragmas the project actually reads.
  2. `toSafeId(value: number | bigint)` — normalizes `lastInsertRowid`, rejects non-safe integers.
  3. Typed prepared statements — `db.prepare<[string], LinkRow>(...)` so binds and result rows are
     declared at the call site.
- `LinkRow` is declared once and mapped to domain objects in the repository; driver row types do
  not leak upward.

## Alternatives considered

- **`node:sqlite`**: built in, but experimental in the target line with a different statement API.
- **`sqlite3`**: callback-based and requires a native build; contradicts the synchronous design.
- **An ORM** (Drizzle, Prisma): a large dependency, generated schema and migration machinery the
  brief never requested.
- **Local `declare module` overrides**: removes the DefinitelyTyped dependency at the cost of
  hand-maintained driver types — more code than two helpers.
- **`any` casts at call sites**: rejected; it defeats strict mode and trips `no-unsafe-*` (D11).

## Consequences

- The typings lag the JS package (9.6.0 vs 13.2.0), so new API surface may need another helper
  rather than a cast; that is reviewed case by case.
- `skipLibCheck: true` (D10) keeps the typings' older `typeScriptVersion` harmless.
- `is_custom` is typed `0 | 1` rather than `boolean`, matching what SQLite stores.

## Implementation impact

- `TASKS.md` §2 adds the typed wrapper tasks instead of suppressions.
- `docs/database-design.md` documents the pragma-reading helper and the timestamp rules.
- `docs/coding-standards.md` forbids `any`, `@ts-ignore`, and non-null assertions where narrowing
  is possible.

## Verification

Manifest facts (`engines`, `files`, `gypfile`, absence of `types`) verified 2026-11-18. Wrapper
sufficiency and prebuilt-binary loading are **unproven** until installation and compilation.
