# ADR-013: Node.js 24 LTS as the supported runtime

- Status: Accepted
- Date: 2026-11-18
- Decision owner: User
- Register entry: D13 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

The runtime determines the `@types/node` major, the driver's engine compatibility, `import.meta`
availability, and the support window of a portfolio project. Node 24 has been Maintenance LTS since
2026-10-20 with support to 2028-04-30; `better-sqlite3` requires `>= 22`.

## Decision

Target **Node.js 24 LTS**:

- `.nvmrc` containing `24`.
- `"engines": { "node": "^24.0.0" }` in `package.json`.
- A committed `package-lock.json`.
- **No** `engine-strict`, so a newer local Node can still run the project while only 24 is
  declared supported.

## Alternatives considered

- **Node 26** (current Active LTS): the cloud sandbox ran it, but it shortens the support horizon
  and is newer than many CI images for no feature need.
- **Node 22**: narrows the window unnecessarily; `better-sqlite3` already supports it.
- **`engine-strict: true`**: turns an advisory mismatch into a hard install failure without
  improving correctness.

## Consequences

- Contributors on Node 24 or newer can run the project; only 24 is supported.
- `@types/node` is pinned to the 24.x line (`^24.19.2`).
- The build output is plain ESM JavaScript with no engine-specific flags.

## Implementation impact

- `docs/ai-workflow/TASKS.md` §1 adds `.nvmrc` and `engines`.
- `README.md` documents the Node 24 requirement.
- `docs/ai-workflow/PROJECT_STATE.md` records the runtime actually available.

## Verification

Release schedule and `better-sqlite3` engines verified 2026-11-18. The user's machine runs
**Node 24.22.1** (`npm 12.2.1`), which satisfies the target; the earlier Node 26.13.0 mismatch came
from a cloud sandbox, not from this environment.
