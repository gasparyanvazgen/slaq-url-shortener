# ADR-014: Caret ranges plus a committed lockfile

- Status: Accepted
- Date: 2026-11-18
- Decision owner: User
- Register entry: D14 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

The project must be reproducible for a reviewer while still accepting patch and minor fixes. The
reviewed versions were verified individually on 2026-11-18.

## Decision

- Declare dependencies with caret ranges in `package.json` (for example `"express": "^5.3.0"`).
- Commit `package-lock.json`.
- Install with `npm ci` when a lockfile exists.
- No `latest` tags and no exact pins.

## Alternatives considered

- **Exact pins**: maximally reproducible, but security updates become a manual edit per package.
- **`latest`**: unreviewable and silently changes majors.
- **Floating ranges without a lockfile**: not reproducible at all.

## Consequences

- `npm ci` installs exactly the reviewed tree; `npm install` updates the lockfile when a range is
  widened.
- A caret range can still pull a minor release with a behavior change, which is why the lockfile is
  committed rather than regenerated in CI.
- Every dependency decision (D8, D10–D13) feeds this lockfile.

## Implementation impact

- `TASKS.md` §1 commits the lockfile and uses `npm ci` in repeatable setup.
- `README.md` documents install and run commands.
- `docs/research-findings.md` §2 records the approved ranges.

## Verification

npm lockfile v3 semantics; registry versions for every package were re-checked on 2026-11-18. No
lockfile exists yet, so resolution is unproven.
