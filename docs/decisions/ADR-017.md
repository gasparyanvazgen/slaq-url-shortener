# ADR-017: API response contracts, `PUBLIC_BASE_URL`, and Host-header safety

- Status: Accepted
- Date: 2026-11-18
- Decision owner: User
- Register entry: D17 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

## Context

Clients need a complete, stable response body, and short URLs must have a trustworthy origin. A
base URL derived from the request `Host` or `X-Forwarded-Host` header lets an attacker mint links
pointing at their own host and enables cache poisoning. The contract also had three undecided
sub-options.

## Decision

- `shortUrl` is built **only** from a validated `PUBLIC_BASE_URL`; `Host` and `X-Forwarded-Host`
  are never read for URL construction.
- `PUBLIC_BASE_URL` is validated at startup: trimmed, ≤ 2048 characters, absolute, `http:` or
  `https:` only, no credentials, no path except `/`, no query, no fragment; normalized with
  `new URL(value).origin`.
- Development default when unset: `http://localhost:${PORT}`. An invalid value fails in every
  environment. Production with the value unset or invalid **fails fast** before the server listens.
- Response contracts as documented in `docs/api-specification.md`: create returns `201` with
  `Location` and `{ code, shortUrl, originalUrl, createdAt, expiresAt, isCustom }`; statistics
  return `200` with `Cache-Control: no-store` and
  `{ code, shortUrl, originalUrl, createdAt, expiresAt, isExpired, isCustom, clickCount, lastClickedAt }`.
- Error envelope `{ error: { code, message, details? } }` with the fixed code table
  (`VALIDATION_ERROR`, `RESERVED_ALIAS`, `NOT_FOUND`, `ALIAS_TAKEN`, `LINK_EXPIRED`,
  `INTERNAL_ERROR`).
- **Sub-options, resolved:**
  - (a) Statistics for an expired link return `200` with `isExpired: true` and the retained count,
    not `410`.
  - (b) `isCustom` is exposed in create and statistics responses.
  - (c) Production behaviour is fail-fast, not warn-and-continue.

## Alternatives considered

- **Derive the origin from `Host`**: zero configuration, but attacker-controlled and unsafe.
- **Return a relative `shortUrl`**: no configuration, but unusable for sharing and copy-paste.
- **Warn instead of failing in production**: serves links pointing at the wrong origin silently.
- **`410` for expired statistics**: hides the retained count and contradicts the retention rule
  (D7).
- **Omit `isCustom`**: less data for the client; the flag is not sensitive and explains why a code
  looks hand-written.

## Consequences

- A deployment that forgets `PUBLIC_BASE_URL` crashes immediately instead of serving bad links.
- Rejecting values with a path is intentional: the redirect route is mounted at the root, so a base
  with a path would produce incorrect short URLs. A trailing `/` is normalized rather than
  rejected.
- Exposing `isCustom` and `originalUrl` means statistics reveal the destination; this is accepted
  for a portfolio MVP and documented in `docs/security-guidelines.md` (no authentication, D9 keeps
  deletion out of scope).

## Implementation impact

- `docs/api-specification.md` documents the bodies, headers, and error table as the contract.
- `docs/security-guidelines.md` records the Host-header rule and the fail-fast policy.
- `docs/testing-strategy.md` adds configuration tests and a Host-injection regression test.
- `docs/ai-workflow/TASKS.md` §7 implements the statistics and expired-link behaviour accordingly; §1 adds startup
  configuration validation.
