# ADR-023: Serve Swagger UI from the API

- Status: Proposed
- Date: 2026-11-19
- Decision owner: User
- Register entry: D23 in [`DECISION-REGISTER.md`](DECISION-REGISTER.md)

> The user explicitly approved **one** new runtime dependency, `swagger-ui-dist`, for this task and
> asked for this ADR to remain **Proposed** until further approval. The dependency approval does not
> make D23 an approved decision; no other dependency, route, or decision is approved here.

## Context

FR-12 (`docs/requirements.md`) requires the REST API to be documented. That work produced the
hand-maintained `docs/openapi.yaml` (OpenAPI 3.1), but it is only readable as a file; there is no
in-app viewer. D3 places every non-redirect route under `/api` or `/health` and registers static
routes before `GET /:code`; D6 reserves `api` and `health` case-insensitively. A top-level `/docs`
would compete with the short-code namespace and change the reserved-alias contract, so it is out of
scope. D14 requires a caret range in `package.json` and a committed lockfile.

## Decision

- Add **`swagger-ui-dist@^5.35.1`** as the single new runtime dependency. Registry check on
  2026-11-19: `5.35.1` is `latest`, it publishes no restrictive `engines` field, and it ships static
  browser assets, so it is usable on Node.js 24 (D13). Its only transitive package, `@scarf/scarf`,
  is install-time analytics and does not run at runtime.
- Register three routes under `/api`, **before** `GET /:code` and the not-found handler:
  - `GET /api/docs` — a small HTML page that loads Swagger UI from `/api/docs/assets/` and
    initializes `SwaggerUIBundle({ url: '/api/openapi.yaml' })`.
  - `GET /api/docs/assets/*` — `express.static` over the installed `swagger-ui-dist` package
    directory, resolved from the serving module's URL.
  - `GET /api/openapi.yaml` — the existing spec file with an `application/yaml` content type.
- Resolve `docs/openapi.yaml` **relative to the serving module's URL** (`import.meta.dirname` or
  `fileURLToPath(import.meta.url)`), never `process.cwd()`. The same relative path works for `tsx`
  from `src/` and for `node dist/server.js` from any working directory.
- Change the OpenAPI `servers` entry to a relative URL (`/`) so Swagger UI's "Try it out" calls the
  origin that served the page; this stays consistent with `PUBLIC_BASE_URL` when that origin is the
  public base. Document that browsers follow the `302` from `GET /{code}`, so a "Try it out" response
  shows the destination rather than the raw redirect.
- Do **not** add `/docs` at the top level and do **not** change the D6 reserved aliases.

## Alternatives considered

- **`swagger-ui-express`**: bundles its own Express middleware and a second dependency wrapper. It
  would add another runtime package beyond the user's approval and gives less explicit control over
  route placement and asset paths.
- **CDN-hosted HTML page**: no npm dependency, but the viewer breaks offline and depends on a third
  party for a documentation route; it also contradicts the choice to ship the assets locally.
- **Pre-rendered static HTML**: no dependency, but loses interactive "Try it out" and would need
  regeneration whenever `docs/openapi.yaml` changes.
- **Top-level `/docs`**: shorter URL, but competes with `GET /:code` and would require widening the
  D6 reserved-alias set. Rejected to keep the approved routing boundary unchanged.

## Consequences

- One new runtime dependency plus its lockfile entry (D14); `npm ci` keeps installs reproducible.
- `docs/openapi.yaml` is read from the repository at runtime, not copied into `dist/`. A deployment
  must ship `docs/` alongside `dist/`; running the compiled server from another working directory
  is explicitly supported because the path is module-relative.
- Static assets come from the installed package directory, so no vendored browser files are added to
  the repository.
- The new routes are unauthenticated and readable by anyone who can reach the service, like the
  rest of the documented API; no new error code or database access is introduced. Unknown asset
  paths fall through to the existing `404 NOT_FOUND` envelope (D3).
- Browsers follow redirects: trying `GET /{code}` in Swagger UI navigates to the destination, so the
  raw `302` is only visible with a client that does not follow redirects.
- D23 remains **Proposed** until the user approves it; this implementation is limited to the
  explicitly approved dependency and route design and introduces no other decision.

## Verification

- Tests written first: `/api/docs` returns `200` HTML, `/api/openapi.yaml` returns `200` with the
  spec content, an unknown `/api/docs/...` path returns the `404 NOT_FOUND` envelope, and
  `/health`, `/:code`, and the reserved aliases are unchanged.
- Build and run `dist/server.js` from a different working directory and request all three new routes
  with `curl`, including a missing-asset `404` check.
- `npm run typecheck && npm run lint && npm test && npm run build` must pass (AGENTS.md §8.2).
